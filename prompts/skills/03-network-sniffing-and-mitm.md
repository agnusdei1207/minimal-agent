# 03. Network Sniffing & MITM

When: Operating on the same local L2/L3 network segment, or positioned in the traffic transit path of target nodes.

## Mental model
Network protocols establish trust based on unauthenticated layer transitions and broadcast assumptions. An attacker captures data by (a) passively observing unencrypted channels, (b) dynamically redirecting traffic routing (spoofing/poisoning), or (c) downgrading transport security.

## Attack arc
- Passive Capture: Sniff interfaces with `tcpdump` or `tshark`; filter for cleartext protocols (HTTP, FTP, Telnet, SNMPv1/v2c, unencrypted LDAP, SMTP).
- Traffic Redirection (L2/L3 Spoofing):
  - *ARP Poisoning:* Send unsolicited ARP replies to poison target & gateway caches (`arpspoof`, `bettercap`).
  - *Broadcast / Multicast Poisoning:* Respond to LLMNR, NBT-NS, and mDNS broadcast queries to harvest NetNTLM hashes or poison DNS (`Responder`).
  - *Rogue DHCP / ICMP Redirect:* Inject malicious DNS server addresses or gateway routes.
- Protocol Downgrade & Relay:
  - Strip TLS on vulnerable legacy flows (SSL/TLS stripping).
  - Relay NTLM authentication to un-signed SMB, LDAP, or HTTP services (`impacket-ntlmrelayx`).
- Packet Crafting: Construct custom stateful/stateless packets with Scapy to test firewall rules or inject TCP resets.

## Key techniques & primitives
- NetNTLM Relaying: Capture SMB/HTTP authentication requests generated by coerced authentications and relay directly to LDAP for privilege escalation or SMB for shell execution.
- SNMP Community Mining: Brute-force community strings (`public`, `private`, `manager`) to dump routing tables, process lists, and interfaces via SNMP MIB trees.

## Tells & signals
- Active LLMNR / NBT-NS broadcasts on Windows subnets = immediate hash-harvesting or relay opportunity.
- Cleartext management protocols (Telnet on port 23, unencrypted HTTP management) leaking admin credentials.
- Lack of SMB signing or LDAP signing enabled across domain controllers and member servers.
