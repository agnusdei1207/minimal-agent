# INTENT-0003 · Shell Execution Model and Interactive Terminal Primitives

- 상태: 진행 중
- 작성: 2026-09-08
- 갱신: 2026-09-12 12:56 KST

## 왜

모의해킹/CTF 에이전트는 `sudo` 비밀번호 입력, `nc` 인터랙티브 챌린지, `gdb`, 리버스 셸, REPL 같은 대화형 프로세스와, 전수 포트 스캔·브루트포스·상시 리스너 같은 장기 실행 작업을 다뤄야 한다. 이를 위해 흔히 쓰는 "별도 PTY 데몬 + Unix Domain Socket(UDS) IPC + 센티널(sentinel) 파싱" 구조는 실전에서 심각한 결함을 드러냈다: (1) IPC·소켓 수명주기·FD 누수·좀비 정리로 런타임 부담이 폭증하고, (2) 입력을 능동 소비하거나 서브셸을 띄우는 프로그램에서 센티널 토큰이 왜곡·누락되어 에이전트가 타임아웃까지 블로킹되며, (3) 타깃(컨테이너·BusyBox·Windows)의 사소한 차이에도 셸 승격 상태머신이 실패하고, (4) POSIX `openpty` 전용이라 크로스플랫폼이 어렵다.

핵심 질문은 "LLM 에이전트에게 필요한 터미널 상호작용의 본질은 무엇이며, OS의 터미널/프로세스 관리자를 프레임워크가 다시 구현해야 하는가"이다. LLM은 사람처럼 키보드를 타건하고 모니터를 응시하는 존재가 아니라 이산적 턴(Turn) 단위로 도구를 호출하는 모델이므로, 프레임워크가 터미널 에뮬레이터를 흉내 내는 것은 유연성을 제한하고 버그의 온상이 된다. 리버스 셸의 "덤프 셸(dumb shell)" 문제(제어 tty 없음 → job control·`sudo`·에디터·프롬프트 깨짐)의 본질도 코어가 아니라 실제 tty를 가진 세션 관리자를 확보하는 것이며, OS가 이미 tmux로 그것을 제공한다. 이 문서가 서면, 코어는 PTY/IPC를 재구현하지 않고 얇은 패스스루만 유지하면서 대화형·지속형·장기 작업을 모두 표현할 수 있다.

## 무엇

- 에이전트는 거의 모든 작업(정찰, 파일 I/O, curl, 익스플로잇 실행)을 기존 `bash` 도구로 한 턴 안에 동기 실행하고 확정적 출력을 즉시 얻는다.
- 명령의 성격에 따라 에이전트가 실행 제한 시간을 스스로 정할 수 있다(빠른 탐색은 짧게, 무거운 스캔은 길게).
- 지속형/대화형 세션(PTY 확보, 백그라운드 리스너, REPL stdin 주입)은 OS 네이티브 tmux를 그대로 호출하는 범용 `tmux` 도구로 처리한다.
- 장기 작업은 메인 턴 루프를 블로킹하지 않고 백그라운드 또는 worker로 격리되며, 프로세스는 누수·좀비 없이 회수된다.

## 수용 기준

- [ ] `tmux` 도구가 `{args: string}` 단일 파라미터로 등록되어, `tmux <args>`를 `bash`와 동일한 일회성 셸 메커니즘(동일 spawn/타임아웃/출력 바운드/취소/에러 규약)으로 실행하고 파이프·리다이렉션이 그대로 동작한다 (입력 `capture-pane -p -t s | tail -n 50` → 정제된 화면 텍스트 반환).
- [ ] `bash` 도구가 선택적 `timeout_secs`(integer, minimum 1)를 받아 지정 시 그 초를 deadline으로 적용하고, 생략 시 기본 300초로 폴백해 기존 호출과 100% 하위 호환된다.
- [ ] tmux 4대 패턴(세션 생성 `new-session -d -s`, 키 주입 `send-keys ... Enter`, 화면 캡처 `capture-pane -p`, 정리 `kill-session`)이 Rust 코어에 새 메커니즘 추가 없이 `tmux` 도구만으로 실현된다.
- [ ] 서브프로세스가 3중 회수(코어 `kill_on_drop(true)`+`stop_child` 프로세스 그룹 시그널, 컨테이너 `--init`/tini PID 1 좀비 수거, `tmux kill-session` 프로세스 트리 일괄 수거)로 타임아웃·취소·종료 시 누수·좀비 없이 회수된다.
- [ ] base 이미지에 `tmux`와 `socat`이 존재하고, 공통 기초 공격 도구가 사전 탑재되며, 에이전트 사용자(UID 10001)에게 `NOPASSWD:ALL` sudo가 부여되어 런타임 자율 설치가 가능하다.

## 제약

- **실행 모델 이원화(불변식)**: 동기 기본 95%(`bash`) + 명시적 비동기 5%(`tmux new-session -d`). 작업의 95% 이상은 직전 출력을 보고 다음 행동을 정하는 순차적 인과 의존(`ls` → `cat config.php` → `mysql`)을 가지므로 동기 실행을 기본으로 강제한다. 10분 이상의 전수 스캔(`nmap -p-`)·대규모 퍼징(`ffuf`)·해시 크래킹(`hashcat`)·상시 리스너만 백그라운드로 격리하고 에이전트는 즉시 턴을 반환받는다.
- **코어는 얇은 패스스루만**: PTY 에뮬레이터·IPC 파이프를 재구현하지 않는다. PTY·세션 상태·수명주기는 전적으로 tmux가 소유한다. `bash`의 무오염 일회성 실행 계약(스키마·동작)은 보존하고, 대화형은 직교하는 별도 `tmux` 도구로 분리한다.
- **base 이미지 계약**: 런타임 base 이미지에 `tmux`(세션·화면 캡처)와 `socat`(완전 pty 업그레이드)이 반드시 존재해야 한다. 이는 doctrine 권고가 아니라 계약이며, 없으면 위 모델이 성립하지 않는다.
- **`timeout_secs` 자율권**: 빠른 실패가 필요한 경량 탐색은 5~15초로 무한 대기를 차단하고, 무거운 단발 작업은 최대 600초까지 에이전트가 부하를 스스로 가늠해 배분한다. 미지정 폴백은 300초.
- **3중 프로세스 회수 보장**: (1) 코어 계층 — `run_shell`이 `kill_on_drop(true)` 명시 + 타임아웃/취소 시 `stop_child`로 자식과 프로세스 그룹 전체에 시그널 전달; (2) OS/인프라 계층 — 모든 컨테이너 기동에 `--init` 강제로 tini가 PID 1을 점유해 고아·`<defunct>` 좀비를 0ms 커널 수준 수거; (3) 세션 계층 — `tmux kill-session -t <name>`으로 하위 프로세스 트리 일괄 회수.
- **세션 격리**: 세션이 필요하면 run-id로 네임스페이스(`ma-<runid>-<name>`)해 고아 세션을 식별·수확한다. 전역 셸 환경변수·디렉터리 상태를 공유해 에이전트 경계를 무너뜨리지 않는다.
- **팀 버스는 신호용**: tmux 캡처 출력(최대 128 KiB)을 4 KiB 팀 메시지(INTENT-0001 §6.3)로 중계하면 경계에서 잘리므로, 화면은 세션에서 직접 읽거나 파일로 넘기고 팀 버스는 신호용으로만 쓴다. 세션 IPC를 팀 버스로 오해하지 않는다.
- **사전 탑재 + 런타임 자율 설치**: `docker/runtime-base.Dockerfile`에 네트워크/정찰(`nmap`, `masscan`, `nikto`, `gobuster`, `ffuf`, `hydra`, `sqlmap`, `socat`, `tcpdump` 등), 바이너리/리버싱/크립토(`gdb`, `gdbserver`, `patchelf`, `strace`, `hashcat`, `john`, `binwalk`, `pwntools`, `ropgadget`, `z3-solver`, `scapy` 등), 웹/트래픽(mitmproxy, requests, httpx, wordlist `rockyou.txt`)을 사전 탑재하고, 컨테이너에 `NET_RAW`/`NET_ADMIN` cap을 부여한다(`docker/compose.yaml`). 사전 탑재되지 않은 도구가 필요하면 에이전트는 멈추거나 사용자에게 요청하지 않고 `sudo apt install -y`, `pip install`, `cargo install`, `git clone`으로 직접 설치해 과업을 완수한다(Script-First 원칙: 특수 프로토콜/익스플로잇은 즉시 전용 Python/Shell 스크립트 작성).
- **장기 작업 격리**: 장시간 스캔·브루트포스·상시 리스너는 INTENT-0001의 2-Depth Worker 에이전트에게 위임한다. `main`은 `team create`로 전담 worker를 만들고 즉시 복귀하며, worker는 완료 시 `team send kind=insight`로 핵심 결과만 보고한다.
- **관련 문서**: INTENT-0001(최소 코어 철학)과 INTENT-0002(승인된 교전 환경)를 잇고, 통합 릴리스는 INTENT-0006, `agent-browser`는 INTENT-0005를 참조한다. Repository: `agnusdei1207/pentesting`.

## 비범위

- **별도 IPC 데몬 프로세스 구축 금지**: UDS 소켓, 백그라운드 리스너 데몬, 전용 클라이언트 라이브러리를 만들지 않는다.
- **문자열 기반 센티널 주입 금지**: 명령 앞뒤로 난수 UUID를 래핑하는 불안정한 기법을 쓰지 않는다.
- **가상 터미널 에뮬레이터 재구현 금지**: ANSI 정제, 링버퍼, 커서 상태 추적을 Rust 코어로 짊어지지 않는다.
- **전역 세션 오염 허용 금지**: 단일 프로세스 공간에서 전역 셸 상태를 공유해 에이전트 간 경계를 무너뜨리지 않는다.
- **전면 비동기/백그라운드 호출 모델 금지**: 모든 도구를 백그라운드로 실행하면 (1) 파일 쓰기/실행 경쟁 상태, (2) 결과 폴링(`sleep`) 루프로 인한 턴·토큰 3~4배 폭증, (3) 잊힌 백그라운드 프로세스 누적 OOM을 유발하므로 절대 허용하지 않는다.
- **개별 전용 공격 도구 표면 세분화 금지**: `nmap_scan`, `sqlmap_run`, `gdb_disasm` 같은 기능별 Function Tool 수십 개 대신 `bash`/`tmux`·`workspace`·`team` 범용 도구 체제를 유지한다(전용 스키마는 매 턴 3,000~6,000 토큰 잠식, 파이프라인 조합성 붕괴, LLM은 표준 Bash/Python에 최적화). 온디스크 스킬/방법론 라이브러리는 코어 도구 표면 결정이 아니라 doctrine·이미지 자산 계약의 문제로 이 문서 범위에서 분리한다.

## 열린 질문 → 결정

- 결정: **`shell`/`bash`에 `stdin` 파라미터 추가는 기각.** 일회성 stdin 일괄 전송(`sudo -S`, 사전 구성 `nc` 질의/응답)에는 충분하나 지속형 세션·백그라운드 리스너·턴을 가로지르는 REPL은 표현하지 못하고, 기존 스키마/불변식을 건드리는 부담 대비 이득이 작다. 필요한 것은 상태를 가진 세션 관리자이며 OS가 이미 tmux로 제공한다.
- 결정: **`bash`→`shell` 리네임 기각.** 도구명을 바꿔 의미를 확장하는 것은 실익 없이 스키마/동작 계약과 프롬프트 자산만 흔든다. 무오염 일회성 계약을 그대로 두고 대화형은 별도 `tmux`로 직교 분리한다.
- 결정: **공용 책상(shared named session) + 단일 기록자 모델 대체됨.** 하나의 이름 붙은 tmux 세션을 팀 공유 자원으로 두고 여러 에이전트가 attach해 "한 번에 한 명만 타이핑", 조종간을 팻말처럼 넘기며 단일 기록자·run-id 네임스페이스·자동 정리·자원 상한을 런타임이 강제하는 안이었다. 범용 `tmux` 패스스루가 세션 생성/키 주입/캡처/정리를 이미 포괄하므로 공유·기록권 조정 같은 무거운 런타임 관리 계층은 채택하지 않는다(필요 시 run-id 네임스페이스 관례로 충분).
- 결정: **PTY 데몬 + UDS/RPC 제어평면 기각.** 수천 줄 코어·크로스플랫폼 부담. tmux가 이미 검증된 형태로 제공한다(레거시 `../pentesting`은 이 무거운 경로를 택했고, 본 저장소는 clean-room 경량 경로 — reference-only, 포팅하지 않음).
- 결정: **세션 소유 worker + 형제 RPC 중계 기각.** 모든 I/O에 모델 턴이 끼어 느리고 4 KiB 팀 메시지 경계에서 화면이 잘린다. 각 에이전트가 tmux 세션에서 직접 읽는 편이 더 가볍고 자율적이다.
- 결정: **방법론을 프롬프트에 전부 굽기 기각.** a-z 지식을 매 턴 고정 비용으로 얹는 대신 온디스크 라이브러리 + 선택적 읽기가 토큰 효율·자율성에서 우위다.
- 결정: **모든 도구 전면 백그라운드화 기각.** 인과적 의존성이 깨져 턴 3~4배 폭증·프로세스 누수·경쟁 상태를 유발하므로 "95% 동기 + 5% 명시적 비동기" 모델을 유지한다.
