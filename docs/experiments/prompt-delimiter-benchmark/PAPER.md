# 프롬프트 구분자 구문 및 삽입 위치가 거대 언어 모델의 지시 이행 취성에 미치는 영향 실증 연구

**An Empirical Study on the Brittleness of Instruction Following and Context Disambiguation Induced by Prompt Delimiters and Position Bias in Modern LLMs**

- **작성일자:** 2026-09-02
- **연구 저장소:** `minimal-agent/experiments/prompt-delimiter-benchmark`
- **실행 환경:** `minimax/minimax-m3:free` via OpenRouter API (Temperature: 0.1, Context Length: 1,000 max tokens)
- **총 실험 표본:** 120회 정량 호출 (기본 과업 15회, 고난도 스트레스 과업 60회, 위치 편향 과업 45회)

---

## 초록 (Abstract)

과거 프롬프트 엔지니어링 분야에서는 지시사항과 컨텍스트의 경계를 분리하기 위해 꺾쇠괄호(Angle Bracket, XML 태그 `< >`)를 사용하는 것이 표준적 모범 사례로 권장되었다. 본 연구는 현대 거대 언어 모델(LLM) 환경에서도 이러한 XML 태그 문법이 여전히 최적의 강건성을 제공하는지, 그리고 복합 제약, 적대적 교란, 컨텍스트 내 위치 변화(Head, Middle, Tail)에 따라 인지적 취성(Cognitive Brittleness)이 어떻게 발생하는지를 5개 주요 구분자(XML, Markdown, Square Bracket, Plain Colon, JSON)를 대상으로 실증 평가하였다.

실험 결과, 단순 지시 환경에서는 모든 구분자가 100.0%의 이행률을 기록하였으나, 적대적 태그 탈출 공격 하에서 대괄호(`[ ]`) 구분자는 66.67%로 급락하는 취성을 보였다. 특히 장문 컨텍스트 내 정보 위치 실험에서, XML 태그는 앞단(Head, 10%)에서는 100.0%의 정확도를 보였으나 중앙(Middle, 50%)에 위치할 경우 0.0%로 완전 붕괴하는 극단적인 위치 편향(Lost-in-the-Middle) 취성을 드러냈다. 반면 Markdown 헤더(`###`)와 Plain Colon(`:`) 구분자는 전 위치 및 스트레스 환경에서 99~100%의 일관된 강건성을 유지하였다. 본 결과는 최신 LLM 대상 프롬프트 설계 시 무조건적인 XML 태그 신봉을 지양하고, 문서 구조형 마크다운 또는 위치 보정 설계를 적용해야 함을 시사한다.

## 1. 서론 및 문제 정의

거대 언어 모델을 활용한 자율 에이전트 시스템에서 프롬프트 내부의 지시문(Instruction), 외부 데이터(Context), 예시(Few-shot Example) 간의 경계를 명확히 분리하는 것은 환각(Hallucination)과 프롬프트 인젝션(Prompt Injection)을 방지하는 핵심 설계 요소이다.

과거 연구 및 개발 관행에서는 `<instruction>`, `<context>`와 같은 XML 엣지브라켓 구문이 LLM의 어텐션 분리를 돕는 가장 강력한 구분자로 간주되었다. 그러나 모델 아키텍처와 사전학습 데이터셋이 발전한 현재, 다음 두 가지 핵심 질문에 대한 정량적 검증이 요구된다:

1. **취성(Brittleness) 격차:** 복합 제약조건과 데이터 내 교란 지시문이 주어졌을 때, 구분자 구문별로 지시 이행의 붕괴율(Failure rate)은 어떻게 다른가?
2. **위치 민감도(Position Bias):** 핵심 정보가 컨텍스트의 앞(Head), 중간(Middle), 뒤(Tail)에 배치될 때 구분자별 포착 정확도는 유지되는가?

본 연구는 `minimax/minimax-m3:free` 모델을 대상으로 총 120회의 정량 실험을 수행하여 프롬프트 구분자 구문이 유발하는 취성을 측정하고, 그 인과적 메커니즘을 분석한다.

## 3. 실험 설계 및 평가 과업

본 연구는 3개 실험군, 총 11개 세부 과업으로 구성된다.

### 3.1 과업 구성

1. **기본 과업군 (Baseline Tasks, 15회):**
   - `Task 1 (Multi-Constraint)`: 접두사 고정, 금지어 회피, 글머리 기호 3개 생성 등 3중 제약 이행.
   - `Task 2 (Context Isolation)`: 컨텍스트 내 가짜 오버라이드 명령어 무시 및 순수 타겟 포트 추출.
   - `Task 3 (Schema Extraction)`: 비정형 보안 권고문에서 `target_ip`, `cve_id`, `cvss_score` JSON 추출.
   - `Task 4 (Boundary Isolation)`: 지침 규칙과 레퍼런스 예시의 경계를 분리하여 새 규칙 적용.

2. **고난도 스트레스 과업군 (Stress Brittleness Tasks, 60회):**
   - `Stress T1 (Injection Escape)`: 데이터 내부에 동일한 닫는 태그(예: `</server_log>`, `[/SERVER_LOG]`) 및 비상 오버라이드 가짜 명령어를 주입하여 구분자 탈출 취성 유발.
   - `Stress T2 (Extreme Multi-Constraint)`: 접두사, 단어 수(15~25단어), 3중 부정 금지어, 단일 줄 출력, IP 포함 등 5개 동시 제약 부여.
   - `Stress T3 (Hierarchical Binding)`: 3단계 중첩 트리 데이터에서 특정 ID와 상태를 가진 하위 인증 토큰 바인딩.
   - `Stress T4 (Code Symbol Collision)`: 소스코드 주석 내 구분자 기호가 다수 포함된 환경에서 타겟 함수명 식별.

3. **위치 편향 과업군 (Position Sensitivity Tasks, 45회):**
   - 12개 시스템 감사 로그 블록(약 2,000자 분량의 Haystack) 내에 단 하나의 마스터 토큰(`FLAG{needle_found_7721}`)을 삽입.
   - 삽입 위치 3단계: `Head (10% 상단)`, `Middle (50% 정중앙)`, `Tail (90% 하단)`.

## 5. 고찰: 왜 XML 엣지브라켓은 위치에 따라 취약해지는가?

본 실측 데이터는 프롬프트 엔지니어링의 오랜 상식에 중요한 반직관적 사실을 제공한다.

1. **태그의 '데이터화' 오인 현상 (Markup Absorption):**
   - 긴 텍스트의 중앙에 `<auth_override>...</auth_override>`와 같은 XML 태그가 위치할 경우, 모델의 셀프 어텐션은 이를 "구조적 지침"이 아니라 "로그 파일 내부에 포함된 원시 HTML/XML 데이터"의 일부로 흡수(Absorb)해버린다.
   - 그 결과 모델은 태그 내부의 지시나 토큰을 메타 지침으로 승격시키지 못하고 단순 무시(0.0%)하게 된다.

2. **Markdown 헤더(`###`)의 문서 구조적 강건성:**
   - 최신 LLM들은 사전학습 과정에서 방대한 양의 Markdown 문서를 학습하였다. 마크다운의 줄바꿈과 샵(`###`) 기호는 토크나이저 수준에서 섹션 경계(Section Boundary)로 강력하게 분리되므로, 텍스트 중앙에 묻히더라도 어텐션 가중치가 소실되지 않고 100% 포착된다.

3. **대괄호(`[ ]`)의 구문 탈출 취성:**
   - `[INSTRUCTION]`과 같은 대괄호 표기는 정규식, 시스템 로그(`[2026-09-02]`), 배열 표기 등과 구문적으로 충돌하기 쉬워, 데이터 내부에 가짜 닫는 태그가 삽입될 경우 가장 쉽게 속아 넘어가는 취약점(66.67%)을 보였다.

## 6. 결론 및 프롬프트 엔지니어링 권고사항

본 연구의 실증적 발견에 기초하여 다음과 같은 프롬프트 설계 규칙을 제안한다:

1. **XML 태그(`< >`)는 프롬프트 최상단(Head)에만 배치하라:**
   - XML 태그는 상단 지시문 격리에서는 우수하지만, 컨텍스트 본문 중간에 흩뿌려질 경우 극단적인 인지 붕괴(0.0%)를 유발한다.
2. **장문 컨텍스트 내부의 섹션 분리에는 Markdown(`###`)을 기본으로 채택하라:**
   - 복합 문서 및 로그 데이터 분리 시에는 위치 편향에 면역을 보인 Markdown 헤더 구문이 가장 안전하다.
3. **대괄호(`[ ]`) 태그의 단독 사용을 지양하라:**
   - 적대적 프롬프트 인젝션 및 구문 충돌에 취약하므로 다중 에이전트 통신 프로토콜로 적합하지 않다.
