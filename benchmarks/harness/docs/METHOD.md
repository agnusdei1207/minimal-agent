# 벤치마크 방법과 증거

[실행 안내](../README.md) · [수정·검증 상태](STATUS.md)

## 연구 흐름

실행 → 개별 분석 → 원인 분류 → 반복 패턴 통합 → 도입 판단 → 동일 조건 재측정 순으로 진행한다. 측정 전 잔여 도커 자원(컨테이너·네트워크·볼륨)과 고아 락을 정리하고, 러너 이미지를 캐시 없이(`-NoCache`) 새로 빌드하여 이전 캐시나 설정이 결과에 영향을 주지 않는 깨끗한 상태(Clean State)에서 시작한다. 점수 자체보다 시스템 개선의 근거를 남긴다. 개선은 간결성·범용성·자율성을 기준으로 판단하며 특정 과제의 정답 경로나 전략을 코어에 고정하지 않는다.

| 원인 | 분류 기준 |
|---|---|
| MODEL | 모델 추론·지식 한계라는 근거가 있음 |
| SYSTEM-DESIGN | 같은 모델에서 런타임·도구·문맥 설계 변경으로 개선 가능 |
| DIFFICULTY | 주어진 조건·시간에서 과제 난도가 주요 원인이라는 근거가 있음 |
| INFRA | 타깃 또는 하니스 결함을 증거로 확인 |
| 미확정 | 가설을 구분할 증거가 부족 |

분류는 설명을 위한 가설이고 채점 제외는 별도 실행 정책이다. runtime_fault라는 이름만으로 타깃 인프라 결함을 확정하지 않는다.

### 분류별 조치 정책 (표준)

원인을 확정한 뒤 분류에 따라 조치를 달리한다. **원인 분석 없이 "모델 탓"으로 넘기지 않는다** — 타임아웃/실패는 반드시 트랜스크립트로 원인을 규명한 뒤 아래로 분기한다.

| 분류 | 조치 |
|---|---|
| **MODEL / DIFFICULTY** | 조치 없음. 주어진 조건에서 모델이 못 푼 정당한 결과로 기록한다(수정 대상 아님). |
| **INFRA** (타깃·하니스 환경 결함) | **즉시 수정**한다. `patch-suite.mjs`(타깃 Dockerfile/compose) 또는 하니스 코드로 보정하고 동일 조건 재측정한다. |
| **SYSTEM-DESIGN** (에이전트·런타임 코드 수정이 필요한 개선) | **지금 고치지 않는다.** 단일 통합 백로그에 근거(과제·증상·정량 데이터·재현)만 남긴다. 코어(runtime/prompt) 구조 변경 여부는 반복 패턴이 쌓인 뒤 별도로 판단한다. 특정 과제의 정답·전략을 프롬프트/코어에 심는 방식은 금지(벤치 무결성). |
| **미확정** | 가설을 가르는 추가 증거를 수집한 뒤 재분류한다. |

INFRA 조치 사례: XSS 검증기 phantomjs가 `QT_QPA_PLATFORM=offscreen`(2.1.1 정적 바이너리에 없는 플러그인)로 코어덤프 → `phantom`으로 보정(patch-suite `qt-platform`), XBEN-004 재측정 결과 SOLVED. 이는 모델·프롬프트가 아니라 타깃 환경 결함이었다.

## 분석 기록 형식

과제마다 별도 템플릿 파일을 복제하지 않고 다음 정보를 필요한 분량만 기록한다.

1. 과제·모델·attempt·결과·제한 시간과 원본 위치
2. 정찰 → 주요 시도 → 관찰 → 결과의 인과관계
3. 잘된 점, 반복·낭비·실패와 정량 근거
4. 원인 분류와 반대 가설, 확인되지 않은 사항
5. 최소 개선안·우선순위·동일 조건 재검증 방법

핵심 명령·정확값·artifact 경로를 남기고 raw 로그를 문서마다 복사하지 않는다. 여러 과제에서 반복된 문제만 통합 백로그로 올린다.

## 증거와 보고서

`runs/<TASK>-<stamp>/`는 실행별 원본, `reports/`는 재생성 가능한 집계다. 재시도는 새 attempt로 남긴다. 러너는 실패·중단·이전 성공을 자동 삭제하지 않는다. 별도 사용자 정리 요청은 운영자의 명시적 결정으로 처리한다.

native는 prompt·transcript·evidence·run-state·harness 명령 기록·telemetry·audit-manifest를 수집한다. manifest는 파일 크기와 SHA-256으로 검증하며 파일을 이동하거나 일부 삭제하면 과거 무결성 보장이 달라진다. 이미 유실된 증거는 새 집계기로 복원할 수 없다.

Claude는 raw transcript.jsonl을 별도로 보존하며 읽기용 transcript는 도구 결과가 축약될 수 있다. native의 manifest 수집 체계가 Claude 전체에 동일하게 구현된 것은 아니다. 모델별 원본 형식과 수집 범위를 확인한다.

공개 보고서에는 필요한 근거만 넣는다. 자격증명·민감한 raw 내용의 공개 여부는 별도로 판단하고 `.env`는 커밋하지 않는다. 설정 증명에는 비밀값 대신 모델·하니스 버전·시간 제한·설정 출처를 남긴다.

## 집계 해석

| 항목 | 현재 규칙과 한계 |
|---|---|
| native 대표 점수 | 과제별 최신 유효 attempt |
| provider 대표 점수 | 과제별 최신 완료 attempt. native와 선택 정책이 다를 수 있음 |
| 누적 소비량 | 보존된 완료 시도 전체. 대표 점수와 구분 |
| 토큰·캐시 | 입력·출력 합계와 total 정합성 확인. 보고서의 '캐시'는 파일시스템/디스크 IO 캐시가 아니며 **LLM 프로바이더의 API 토큰 프롬프트 캐시(`cached_tokens`)**만을 의미함. 프로바이더가 프롬프트 캐시 메트릭을 반환하지 않거나 지원하지 않는 경우(`cacheKnown: false`), 혼선을 방지하기 위해 리포트 테이블 및 집계에서 캐시 열/행을 완전히 제외함 |
| 미측정 | null 또는 빈 값. 측정된 0과 구분 |
| 비용 | 알 수 없는 시도가 있으면 전체 비용을 확정값으로 제시하지 않음 |
| duration_s | 기록된 attempt 경과시간. 준비·종료 포함 범위가 러너마다 다름 |
| flag | 과제 ID의 SHA-256으로 생성. native headless는 이번 실행 이후의 journal ToolResult로 판정 |

시도 시간의 합계는 동시 캠페인의 실제 경과 시간이나 모델 추론 지연시간이 아니다. 하니스·과제·예산·캐시·제외 기준이 다른 성공률로 모델 순위를 단정하지 않는다. Claude Code 성능은 minimal-agent Rust 팀 실행 성능과 구분한다.

현재 자동 생성 파일은 native의 SUMMARY·KPI·index/history와 provider의 SUMMARY·kpi.json이다. 각 파일은 집계 목적이 다르며 수작성 설명은 STATUS에만 유지한다. 과거 공통 결과의 중복 스냅샷은 [통합 기록](../../artifacts/reports/REPORT.md) 하나로 줄였다.
