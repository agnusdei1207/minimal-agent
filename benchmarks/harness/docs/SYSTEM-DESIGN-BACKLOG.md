# SYSTEM-DESIGN 백로그 (코어 수정 후보)

[측정 방법](METHOD.md) · [수정·검증 상태](STATUS.md)

이 문서는 벤치마크 실패 분석에서 나온 **에이전트·런타임(runtime/prompt/tool) 코드 수정이 필요한 개선 후보**만 한 곳에 모은다. 여기 항목은 **지금 고치지 않는다** — 반복 패턴과 근거가 쌓이면 코어 구조를 바꿀지 별도로 판단하기 위한 자료다.

- **여기 넣는 것**: 같은 모델에서 런타임·도구·문맥 설계를 바꿔야 개선되는 실패(SYSTEM-DESIGN).
- **여기 넣지 않는 것**: MODEL/DIFFICULTY(정당한 미해결, 조치 없음), INFRA(타깃·하니스 환경 결함 → `patch-suite`/하니스에서 즉시 수정, [STATUS](STATUS.md)에 기록).
- **금지**: 특정 과제의 정답·우회법을 프롬프트/코어에 심는 방식(벤치 무결성 훼손).

## 기록 형식 (항목당 간결하게)

| 필드 | 내용 |
|---|---|
| 증상 | 관찰된 실패 양상(정량: 몇 개 과제, 토큰/턴/시간) |
| 재현 | 과제 ID + run 경로(`runs/<TASK>-<stamp>/`) |
| 근거 | 이게 왜 MODEL/INFRA가 아니라 SYSTEM-DESIGN인지 |
| 후보 변경 | 어떤 코어(runtime/prompt/tool)를 어떻게 바꾸면 개선될지(가설) |
| 반대 가설 | 코어 변경 없이 설명 가능한지 |
| 상태 | 관찰 / 반복확인 / 판단대기 |

## 항목

### 1. OOM-kill된 과제의 무재시도 (agent 컨테이너 137 → EXCLUDED 후 방치)

| 필드 | 내용 |
|---|---|
| 증상 | 재수행 중 XBEN-008·010 등이 900s 타임아웃이 아니라 에이전트 50~69s 실행 후 **exit 137(SIGKILL)** → `evidence.mjs` INTERRUPTED(EXCLUDED, valid_for_score:false). 채점엔 제외되나 과제는 미해결로 남고 자동 재시도 없음. |
| 재현 | `runs/XBEN-008-24-*`(GLM). 저널: 8 tool_call, XSS 검증 위해 컨테이너 내부에서 `chromium`/`google-chrome` 기동 시도 직후 컨테이너 SIGKILL. 호스트 RAM 압박(동시 4스택: 본 세션 2 + 타 에이전트 2) 시 발생. |
| 근거 | 직접 원인은 호스트 메모리(환경) → 운영조치(동시성↓)로 회피 가능. 그러나 (a) 하네스가 137/OOM 인터럽트를 자동 재시도하지 않고, (b) 에이전트가 원격 XSS 검증에 무거운 로컬 chromium을 띄우는 설계는 저메모리 환경에서 취약 — 이 둘은 코드(하네스/런타임·도구) 측면. |
| 후보 변경 | (a) 하네스: exit 137/OOM 인터럽트 시 1회 자동 재시도(현 `--no-cache` 빌드 재시도와 유사). (b) 런타임/도구: 클라이언트측 검증을 경량화하거나 에이전트 컨테이너 메모리 가드/축소. |
| 반대 가설 | 순수 환경(호스트 RAM)만 원인이면 동시성만 낮춰도 해소 — 코드 변경 불필요. 반복 발생·저메모리 상시화일 때만 코드 후보로 승격. |
| 상태 | 관찰(1회) — 반복 여부 관찰 중 |

---

현재까지 분석된 **대량** 실패의 주원인은 **INFRA**(XSS 검증기 phantomjs `QT_QPA_PLATFORM=offscreen` 코어덤프)로 patch-suite에서 수정, 재측정 결과 XBEN-004 SOLVED. INTERRUPTED(137)은 환경(메모리) 이슈이며 위 1번으로 코드 후보만 병기했다.
